# 生成效果核查与修复（2026-09-09）

本轮范围：角色学习的数据入口、角色/主体语义、推理条件与可复现验证。前端按用户指定顺序留到生成效果验收后处理。

这里的可见区域与负向词是生成条件，不能保证扩散模型绝不产生肢体错误。尤其 3B VLM 仍可能误认姿态、服装覆盖或材质，记录均应视为待核验的模型观察。

## 备份比较的边界

当前与备份的 `test.py` 在本轮开始时只有一处空格差异，`dataset.py` 相同；`config.py` 的训练步数由 500 改为 600。两份 final 权重哈希不同，012/013 也从带环境的小尺寸细节图换成较大的独立素材，因此不能把画面退步归因于某一个推理代码改动。

历史人像记录的 strength=0.75、LoRA=1.15 相同，而且随机种子未保存。当前 final 权重 SHA-256：`C3E509B343296E0B0E858F1A08D106179008DD5205A81AA85D77149B5CE4CEB0`；备份 final：`C25A11BD432F8CEDE5EEA9CFA0921CB3F5CAACEB888A351E9F3763E9FBCEDF47`。

训练仅用 `train_ds[0]` 的去噪损失选 best；该数字不能说明相机、徽章或跨主体迁移都学好了。修复后的数据入口需要重新训练才会影响权重，本轮现有权重的 A/B 只检验推理改动。

## 验证方法与产物

运行环境：`D:\Anaconda\envs\DL\python.exe`，PyTorch 2.2.1+cu121 / Diffusers 0.31.0 / Transformers 4.56.2，本机 RTX 4060 8GB。

代码回归：`python -m unittest discover -s tests -v`。检查半身/遮挡语义、独立配饰标注、全部配饰入选、不拉伸、校核记忆、非人主体隔离，并用本地 SDXL 双 tokenizer 检查现有七张输入的条件长度。

实际 A/B：`python histories/scripts/verify_transfer_revision.py`。每次写新目录 `output/experiments/transfer_revision_<时间>/`，含 `baseline/`、`revised/`、日志和 manifest。两组使用同一输入、同一份 current final、seed=42、同分辨率、36 步；旧组复现历史记录的提示词与分支参数，新组运行修改后的 `test.py`。使用 CPU offload 在本机运行，不改旧 `output/result` 和备份。

实际结果目录：`output/experiments/transfer_revision_20260909_194643/`。

- 同权重、seed=42 的旧配方和修改配方人像都保留了双手，没有新增露腿。因此不能声称这次 A/B 已证明新方法能消除肢体错误；历史失败图仍说明原提示词存在不必要的腿部条件。
- 修改配方（strength=0.64、LoRA=0.9）较保守，保留油画感，但人物身份不足，头发主要仍为深色、服饰迁移弱，脸部还有异常。这不是可直接验收的效果。
- 两组杯子都没有正确生成 013，仍出现近似心形的错误标志。文字描述校正必要，但不足以解决参考图形的精确生成。
- `output/experiments/accessory_refine_20260909_204635/`：局部参考轮廓条件实验，四瓣结构有所接近，但颜色错误、矩形补丁明显。
- `output/experiments/accessory_refine_20260909_205035/`：轮廓形状遮罩 + LoRA=0.5，矩形补丁减轻，但纹样过淡，颜色层次仍不正确。不能认定配饰已学会。
- `output/experiments/identity_balance_20260909_205956/`：沿用已记录的主体观察，seed=42、strength=0.70、LoRA=1.0，并去重核心身份词。粉发/粉眼更明显，保留双手和半身构图，但头发仍大面积黑色、胸饰瓣数/配色不对、眼下出现异常浅色形状；未达标，不能据此把更高强度推广成默认最优值。

局部实验只把参考图的黑白轮廓作为 ControlNet 条件，最终像素来自扩散生成，不是把配饰 RGB 贴到杯子上。实验框由人工检查指定；`vision/accessory_refiner.py` 尚未接入默认推理流程，也不具备可靠的自动定位能力。不能把已知杯身坐标推广到其他物品。

不能用单元测试通过、VLM 自评分或 loss 下降替代图片验收。现有权重未重新训练。

## 范围澄清：通用物品角色化，不是杯子贴花

用户所指的杯子是“非人物主体”的例子，不是功能边界。目标是物品仍保持原有形态、材质感和用途，同时以整体配色、设计细节和标志性造型体现角色特征；不能只生成一个局部标志，更不能把物品变成人物。动物仍作为独立分支保留原生结构，不应套用物品材质规则。

本轮继续修正：

- `character/object_policy.py` 按实际材质和观察到的可装饰表面规划，不再按 cup/bag 名称分流。织物对应刺绣/表面纹样，陶瓷对应釉面纹样，金属或皮面对应压纹等；混合或未知材质保守回退，不强行变成陶瓷。
- 恢复物品和动物分支丢失的角色主/辅/点缀色。物品必需提示词同时保留主体类别、原有形状与部件、角色配色、配饰几何和原图画风；剩余预算加入色块设计与纹理保持。无人工卡片的其他角色也沿用自己的配色，不引用 37 的默认颜色。
- VLM 表面规划必须来自主体观察的 surface_regions；挂件必须有观察到的拉链、环或挂钩等安装点。拒绝凭空添加肩部、脖子、挂点或杯身。耳机的 earcup 不再因为包含 ear 而被错当成动物耳朵。
- 明确保留屏幕、镜头、按钮、开口等功能区域，不把它们列作装饰面。语义检查不等于像素级保护；默认全图 img2img 仍可能改坏功能细节，需要后续掩码定位与图像验收。

回归共 16 项通过，语义案例覆盖杯、背包、耳机、皮面笔记本、木椅、金属盒、花瓶及未知物品；真实 SDXL 双 tokenizer 检查了现有七份主体记录及额外五类物品提示词。这是跨品类**规划与条件长度验证**，不是这些品类都已实际生成并验收。项目 `input/` 当前只有杯子这一类普通物品，其余为人物和猫；尚缺不同材质实物的图像级回归集。

当前生成路径仍以主标志 013 为主要配饰条件；012 已校正语义、训练标注及参考来源，但尚未完成其独立生成保真验证，也没有证明模型能自动把相机造型规律合理迁移到任意物品。不能把人工卡片更正称为权重已经重新学会。

剩余关键工作是：用修复的数据入口建立新权重对照、解决配饰颜色分层和形状保真、验证不同物品上的整体角色特征及结构保护，再决定是否启用局部重绘。当前不能宣称通用角色化已达标。

## 后续前端的接口边界

已核对 `f_example/7.png`、`8.png` 和 `前端实现提示词.md`。前端主题需要角色主体配色统计、配饰素材及统一 CSS 变量映射；图像迁移的“语义重绘配饰”与网页的“使用透明装饰素材”是两个不同输出需求。该前端规格明确允许提取配饰 PNG，因此网页主题不需要等待生成模型每次重新画出一个准确徽章。

后续应直接从已核验角色参考建立主题数据；不要把本轮或旧版生成错误的杯身四叶草当作网页标志来源。前端实现仍按图7 默认页验收、等价变量化、图8 主题接入的顺序进行。
