# 无尽的xxx：问题诊断与修复报告

> 针对"蒙娜丽莎转角色失败 / 统一朦胧画风 / 角色不像 / loss 曲线不下降"四个症状的根因分析、验证实验与修复清单。结论先行：**项目整体设计（LoRA 身份 + ControlNet 结构 + VLM 主体理解）思路可靠，不需要推翻重做**；四个症状分别由 3 个实现级问题 + 1 个监控问题造成，已逐一修复，并给出重训后的验证结果。

---

## 一、症状 → 根因对照

| 症状 | 根因 | 性质 |
|---|---|---|
| 输出统一"朦胧、油画般的软糊"画风，所有图风格一模一样 | ① 推理 prompt 强制 `photorealistic, preserve photographic appearance`；底模 Illustrious 是**动漫模型**，被要求画写实 + Canny 0.9 强结构锁死 → 只出"低频结构 + 柔和渐变"；② 写实方向没有任何负向词抑制（还叠加了 0.9 的 Canny） | 推理侧 prompt 缺陷（最主要） |
| 人物"完全不像角色"（脸/发/服都不对） | ③ 角色身份来自 VLM 解析记忆，Qwen2.5-VL 把 37 号角色的**粉发/蓝白衣/四叶发饰幻觉成 "light blue hair / Flower Fairy / light blue dress with pink flower pattern / teal eyes"**，prompt 里直接写了 "light blue" 发色 → 文本条件压过 LoRA，生成浅蓝发女孩；④ LoRA 本身训练不足：400 步 + 余弦衰减到 0（后半段"停学"）+ 训练裁剪把许多人像图的**脸裁掉**（见 §二.2） | 推理侧 prompt + 训练侧数据/超参 |
| 训练 loss 曲线锯齿、看不出下降 | ⑤ 训练 loss 每个采样点来自**均匀随机的扩散时间步 t**：t 小时 loss 天然≈0.01，t 大时天然≈0.35；batch=1 时相邻两步 t 差巨大 → 曲线大幅震荡。实际梯度一直在更新（已检查保存的 LoRA 权重：lora_B 非零且逐步增长；epoch 均值 0.29→0.12 有下降），只是**被 t 的方差完全淹没** | 监控方式问题（非训练 bug） |
| 配饰"粘贴感"、杯子/猫几乎没变化 | ⑥ 配饰短语注入了 VLM 幻觉记忆（"bow tie / teal four-leaf"）；⑦ 画风/细节词缺失（无 quality tags、无 "highly detailed"） | 推理侧 prompt 缺陷 |

**关键实验（消融验证，同一底模、同一种子、640px、25 步、CFG 7.0）：**

| 变体 | prompt | 结果 |
|---|---|---|
| A | LoRA(旧) + **卡片 prompt**（pink hair…+ anime style） | 粉白渐变发、粉瞳、蓝蝴蝶结、白+蓝服装 —— **角色身份出来了** |
| B | LoRA(旧) + **旧 VLM prompt**（light blue hair…photorealistic） | 浅粉发、**蓝绿瞳**、蓝色发夹、粉色衣服、软糊画风 —— 即用户看到的"不像角色 + 朦胧" |
| C | 无 LoRA + 卡片 prompt | 粉发蓝白服女孩（底模先验），但缺少 LoRA 提供的具体设计细节 |

→ 结论：**旧 prompt（VLM 幻觉记忆 + photorealistic 风格）是"不像角色 + 朦胧"的直接原因**；现有 LoRA 其实已经学到了相当多的身份，只是被 prompt 抵消了。

## 二、训练侧问题（重训时修复）

### 1. 训练数据裁剪把脸裁掉了（dataset.py `make_transforms`）

- 数据：20 张角色图，多为 448×1088 / 1192×2144 等**高瘦全身像**。
- 旧实现：`Resize(640)`（短边对齐）+ `CenterCrop(640)`。
- 对 448×1088 的图：先放大到 640×1554，再裁 640×640 → **裁到腰部到膝盖的中带**，头部/脸/发饰整体出画面。
- 实测 contact sheet（训练时模型真实看到的 20 个样本）：`001/002/003/004/016` 的脸被完全裁掉，全身图的头只有 40px 大小 → 脸身份只在约 6/20 的样本里明确可见，400 步内学不到脸。
- **修复**：新增 `TopBiasedRandomCrop`（80% 概率从画面顶部 40% 高度内随机取窗，20% 全图随机），保证头/发/发饰/上半身主导训练窗口，同时保留少量腿部/构图样本。已验证 001 的裁剪窗口从"腰部"修正为"头+肩+胸"。

### 2. 训练步数与学习率

- 旧：400 步 + cosine（lr 1e-4 暖机 50 步后衰减到 0）。cosine 在 50 步后就在持续降 lr，400 步结束 lr≈0——**后半段几乎没在学**（20 张小样本更需要步数，不是更需要衰减）。epoch 均值仅从 0.29 降到 0.12，欠拟合。
- **修复**：`max_train_steps=1000`（50 epoch），`LR_SCHEDULER=constant`（lr 1e-4），`LORA_RANK/ALPHA=32/32`（23M→46M 参数，显存仅 +~90MB），`SAVE_STEPS=200`。

### 3. 训练 prompt 缺质量词

- 旧：`ch37, 1girl, front view, full body shot`；推理 prompt 却含 `high quality` 等训练时从未出现的词 → 分布偏差。
- **修复**：训练端加入 `TRAIN_QUALITY_TAGS = "masterpiece, best quality"`（与推理端 quality_tags 对齐）。

### 4. captions 与训练图不符（小问题）

- `008.png` 标注 "eyes close-up"，实际是头发特写；`007.png` 标 "face close-up" 实际是侧后发。标注错误影响代表图挑选与 VLM 解析。
- **修复**：更正为 `hair close-up, strand of hair` / `side view, hair close-up, back view`。

## 三、推理侧问题（已修复）

1. **角色身份描述改为人工卡片**（`config.CHARACTER_CARDS`，新增 `get_character_card`）：
   - 卡片字段：`identity_tags`（Danbooru 风格标签，底模熟知的自然语言）、`quality_tags`、`style`、`style_policy`、`palette`、`accessory`。
   - 卡片存在时**不再加载 VLM 语义记忆**（`output/semantic/37_character_memory.json` 已确认是幻觉产物）；VLM 只保留两个职责：**输入主体理解**（human/animal/object）与**配饰迁移规划**。
   - 无卡片角色自动回退旧路径（兼容多角色）。
2. **风格策略**（`style_policy`）：
   - `"character"`（默认）→ 输出统一为角色画风（`anime style`），对应示例图 37_1（油画→动漫）/37_3（涂鸦→动漫）；
   - `"preserve"` → 保留输入画风（对应 37_2 照片猫）。
   - 写实/油画/3D 方向加入负向词（新增 `config.ANIME_NEGATIVE_PROMPT`），阻止动漫底模退回写实朦胧画风。
3. **拟人抑制**：类别词 `1girl` 只注入 human 主体；animal/object 只注入 palette + 配饰短语（"1girl 猫" = 猫娘，规格 §18.2 同理）。
4. **生成参数**：CFG 6.0→7.0，步数 30→36，`CONTROLNET_CONDITIONING_SCALE` 0.9→0.7（0.9 把结构"钉死"，LoRA 身份无法改写发型/服装轮廓）。
5. 删除空词：`character identity` / `natural integration` / `natural material integration` 等（对底模无信息量）。

## 四、"loss 曲线不下降"的真相

- **梯度一直在更新**：直接读取 `output/train_models/37_step_100.safetensors` 与 `37_final.safetensors`，lora_A/B 权重非零且随训练增长（B 矩阵范数 0.19→0.29），确认反向传播有效。
- **曲线锯齿是随机时间步方差**：同一模型在 t=100 与 t=900 的 MSE 天然差 30 倍；batch=1 + 均匀采 t，曲线必然大幅震荡。它的"看得见下降"版本是 epoch 均值（0.29→0.12，确实下降）。
- **修复（让真实进度可见）**：新增 `eval_loss_fixed_timesteps`——每 `EVAL_LOSS_INTERVAL=20` 步，在固定 t∈{150,500,850}、固定噪声上计算评估 loss（难度恒定、可复现）。CSV 新增 `eval_loss` 列，曲线图叠加显示：
  - 蓝色点：训练 loss（锯齿，仅参考）；
  - 橙色实线：**固定 t 评估 loss（平滑，直接显示梯度下降）**；
  - 绿色虚线：训练 loss EMA 平滑。
- **Best checkpoint 选择改用评估 loss**：旧版按"单步训练 loss 最低"选 best，实际选的是"运气最好的 t 采样"（0.0041 这种极值无意义）。现在以评估 loss 最低为准，`{folder}_best.safetensors` 才是真实最优。

## 五、回答四个核心疑问

### Q1：VLM 是否参与了图片效果？是否需要保留？

- **VLM 完全不生成像素**，它只做三件事：写 JSON 语义（角色记忆 / 主体分析 / 配饰规划）、拼 prompt、给结果打分。
- 但它**通过 prompt 间接、且负面地影响了效果**：角色记忆幻觉（粉发→浅蓝发、四叶→bow tie、身份→Flower Fairy）被拼进 prompt，直接覆盖了 LoRA 的身份信号（消融实验 B 已复现）。
- **保留建议：保留，但降级为"辅助"**——
  - ✅ 保留：输入主体理解（分辨 human/animal/object + 材质），这个任务看单张图、稳定可靠，且是猫/杯/人三路 prompt 的分流开关；
  - ✅ 保留（可选）：配饰迁移规划（有合法词表 + 区域校验，失败自动回退规则表，安全）；
  - ❌ 不再使用：VLM 角色身份记忆（已被人工卡片取代）；
  - ❌ 建议关闭：VLM 结果评价（`ENABLE_RESULT_EVALUATION=False`）——实测它对完全没有角色身份的旧结果仍打 0.8 一致性，分数没有区分度，还会多花 2~4 分钟/图。

### Q2：项目实现思路是否可靠？

**可靠，不需要推翻重做。** "角色 LoRA 学身份 + ControlNet 保结构 + img2img/CFG 控制改写强度 + 文本描述引导"是当前角色迁移/风格化的标准工业做法（kohya 生态、SD 角色 LoRA、InstantID 等同类路线）。项目此前失败在**实现细节**（prompt 来源、风格方向、训练裁剪、步数），不在架构。真正保守的做法是：**先用 LoRA + 图生图 + 文生图，验证身份与姿势**（本次已验证），再逐步叠加语义模块。

### Q3：项目损失是否合理？

**合理。** epsilon 噪声预测 MSE + 随机 t + 双 text encoder + added_cond（SDXL 标准配置）就是官方 SDXL LoRA 训练的损失。不合理的是**监控与选择方式**（单步 loss 做 best 选择、无固定 t 评估），已修复。

### Q4：仅调参数能否达到预期？

**不能（仅靠旧参数不行），但也不需要改架构**：主因是三个方面同时出问题（prompt 来源、风格方向、训练裁剪），任何单项目参数调整都治不了"头发颜色被 prompt 写错"或"脸不在训练窗口里"。这三处都已在代码层修复；调参（步数/rank/lr/Canny）只是配合优化。

## 七、重训与验证

### 7.1 朦胧画风根因的定位（消融实验，全程同种子/同 prompt）

| 变体 | 路径 | 结果 |
|---|---|---|
| expA | 文生图 640 + LoRA + 卡片 prompt | **清晰**，粉发蓝白服角色 ✓ |
| expB | 文生图 640 + LoRA + 旧 VLM prompt | 浅粉发/蓝绿瞳/粉衣，**软糊**——旧 prompt 毒性复现 |
| expD | **纯 ControlNet-canny 0.7**（768，无 LoRA） | **朦胧空气感** ← 与 LoRA/prompt 无关 |
| expE/F | 纯 Canny 0.7 + fp32 VAE / fp16 VAE | 同样朦胧 → VAE 精度不是原因 |
| expG | Canny 0.7 @ 640 | 同样朦胧 → 分辨率不是原因 |
| expL | **Canny 0.35** | **清晰** ✓ 身份完整 ✓（姿势被重新演绎） |
| expM | **Canny 0.45** | 清晰 ✓（姿势部分保留） |
| expI | **img2img 0.60** | 清晰 ✓ 姿势保留 ✓（身份部分：原画深发/深衣留存） |
| expN | img2img 0.68 | 清晰 ✓ 姿势保留 ✓（身份同上，略强） |
| expO2 | **img2img 0.60 + Canny 0.40（原生 ControlNet-Img2Img）** | 清晰 ✓ 姿势全保留 ✓ 身份明显增强 |
| expP | **img2img 0.72 + Canny 0.35** | 清晰 ✓ 姿势全保留 ✓ 身份更强（粉发渐变 + 四叶发饰 + 蓝丝带） |

**结论：**
- "朦胧空气感"的根源 = **ControlNet-canny 条件强度 ≥0.7**（ControlNet 特征主导 UNet 各层，压平细节）；与 LoRA、prompt、VAE 精度、分辨率均无关（expD~G 交叉验证）。
- 最优配方 = **img2img + 低 scale canny 混合**：姿势/背景由 init 图像锚定（不再依赖 canny 高 scale），canny 低 scale（0.35）保持清晰，LoRA+prompt 提供身份——三者不再互相打架。
- 已按此改造推理管线：`StableDiffusionXLControlNetImg2ImgPipeline`（config.USE_HYBRID_IMG2IMG_CONTROLNET=True / IMG2IMG_STRENGTH=0.68 / CONTROLNET_CONDITIONING_SCALE=0.35 / INFERENCE_RESOLUTION=640 与训练一致）。

### 7.2 重训（修复后管线）

**训练配置**：640 分辨率 / 1000 步（50 epoch）/ batch 1 / 累积 1 / fp16 / rank 32（alpha 32）/ lr 1e-4 constant / 8bit Adam / 梯度检查点 / 触发词 ch37 / 顶部偏置随机裁剪 / 训练 prompt 注入质量词 `masterpiece, best quality` / 每 20 步固定 t 评估（t∈{150,500,850}）。耗时约 3.4 小时（11~13 秒/步，含评估）。

**训练曲线**（`output/curves/37_loss_by_step.png`，原始数据 `37_train_metrics.csv`）：
- 训练 loss（蓝点）仍保持锯齿——这是**随机时间步 t 的方差**，属正常现象（t 小时 loss 天然≈0.01，t 大时≈0.3）；
- **固定 t 评估 loss（绿线/红点线）清晰显示真实学习进度**：20 步 0.204 → 100 步 0.143 → 约 200 步后进入平台（0.12~0.17 波动）→ 最低 0.116（第 940 步）；
- **结论**：模型在 ~200 步完成主要学习，~500 步后进入平台 → 1000 步对身份绑定仅有边际增益（平台期曲线即证据）。因此 `CHARACTER_PRESETS["37"]["max_train_steps"]` 已调整为 **500 步**（对新角色训练同样适用：观察 eval 曲线平台期即可提前停）。

**身份检查（文生图，仅触发词 + 卡片 prompt，无 img2img 干扰）**：输出（`output/identity_check.png`）已明确还原角色——粉白渐变发、粉紫瞳、四叶发饰、choker、蓝黑渐变连衣裙 + 白色分离袖、青黑束腰、蓝丝带、橙红相机腰包、佩带蓝丝带过膝袜。**训练侧修复（裁剪 + 步数 + rank + 质量词）确认有效**。

**最终三图复测**（`output/result/`，混合路径 img2img 0.72 + canny 0.35，640px，全链路 VLM+SAM+LoRA）：
- **蒙娜丽莎（human）**：坐姿/交叉双手/三分之四侧脸/背景风景完整保留；角色身份显著迁移（粉发白刘海、粉红瞳、choker、蓝白服饰、四叶肩部配饰）；画风为角色动漫风格（清晰度较旧版"朦胧"大幅改善，保留部分原画深色发尾属 0.72 强度下的正常折衷；如需更强身份可用 `IMG2IMG_STRENGTH=0.78`，实验见 `output/experiments/expQ_human_078.png`）。
- **猫（cat）**：原猫的姿势/环境完整保留；**四叶花配饰作为耳饰** + 蓝粉项圈/毛色微调——对应示例图 37_2 的"动物 + 角色配饰/配色"路径。
- **杯子（cup）**：杯形/手柄/桌面静物完整保留；**角色青蓝色四叶饰纹 + 粉白渐变配色转移到杯身**——对应示例图 37_2 路径的"物品 + 角色配饰/配色"。

**总结**：此前四个症状全部有明确根因并已修复——①"统一朦胧画风"= ControlNet-canny 高 scale 压制细节（→ 混合路径低 scale）；②"完全不像角色"= VLM 幻觉记忆污染 prompt（→ 人工卡片）+ 训练裁剪掉脸（→ 顶部偏置裁剪）；③"动物/物品没变化"= 画风指令互相抵消（→ 风格策略统一）；④"loss 不下降"= 随机 t 方差淹没（→ 固定 t 评估 + EMA，曲线可见真实下降）。

### 7.3 V3 重训与最终复测 v4（2026-08-29）

**重训（v3 管线，500 步）**：混合内容裁剪（30% 整图桶 + 50% 顶部偏置 + 20% 随机，桶尺寸 64 倍数、≤9 种固定分辨率，保证推理速度）+ 固定评估集 dataset[0] + 精确 quality 词。**评估 loss：0.212 → 0.162，平滑单调下降，~150 步后进入平台**（`output/curves/37_loss_by_step.png` 绿线为严格平滑曲线——此前"曲线看不出下降"的问题彻底解决）。
**身份检查**（`output/experiments/identity_check_v3.png`）：蓝色外套+白分离袖+金扣白衬衫+蓝黑束腰+四叶发饰+腰侧相机——服装细节与卡片精确标签一致，较 v2 版本更贴合角色原设。
**最终复测 v4**（`output/result/`，混合路径，人物 0.72/0.35、物品 0.68/0.40、动物 0.70/0.38，LoRA=v3 final）：
- 蒙娜丽莎：姿势/表情/背景完整保留；**角色精确服装**（白衬衫金扣+深蓝外套+白色分离袖+蓝背带+choker 蓝宝石+粉发白刘海+粉紫瞳）明显优于 v2 复测（深色残余为 0.72 强度下的折衷，如需更彻底换装可试 `IMG2IMG_STRENGTH=0.78`）。

- 杯子：杯形保留；**青蓝四叶徽章纹清晰成型**于杯身（V2 的"模糊圆点"已消除）。

## 八、方案演进史（V1 → V2 → V3，淘汰方案复盘）

> 每代方案按「介绍方案 → 最终效果的问题 → 问题原因 → 改进到下一方案做了哪些处理」记录。

### V1 方案（初版交付，问题最多）

**介绍方案**：训练用 `Resize(短边640) + CenterCrop(640)`、rank 16、cosine lr、400 步；角色身份由 Qwen2.5-VL 从 3 张代表图解析成语义记忆（`output/semantic/*.json`）；推理 prompt 合成"photorealistic, preserve photographic appearance + VLM 记忆配色 + 配饰短语"；结构保持用 ControlNet-canny 0.9；每图 30 步 / CFG 6；结果由 VLM 打分评价。

**最终效果的问题**：①所有输出统一"朦胧油画感"，无细节；②人物完全不像角色（脸/发/服都不对）、配饰有粘贴感；③动物/物品几乎没有任何变化；④loss 曲线纯锯齿、看不出下降；⑤VLM 评价分数失真（对"没有角色身份"的结果打 0.8 一致性）。

**问题原因**：
- ① + ②的 prompt 侧：底模 Illustrious 是动漫模型，却被要求"photorealistic"；VLM 幻觉记忆（粉发→"light blue hair"、四叶→"bow tie"、身份→"Flower Fairy"）被拼进 prompt 直接覆盖 LoRA 身份。消融 A/B/C 证明：同一 LoRA，旧 VLM prompt 出浅蓝发女孩，卡片 prompt 出粉发角色。
- ②的训练侧：CenterCrop 把 448×1088 全身图裁成"腰部中带"，脸、发饰整张丢失（contact sheet 证据：001~004/016 无脸）；400 步 + cosine 在 50 步后持续降 lr，实际学习量不足。
- ③：正向词"photorealistic" + 负向"anime girl/1girl" 双向压制 + canny 0.9 钉死结构 → 模型只能输出原图 + 金项链。
- ④：监控缺陷（随机 t 方差，非训练 bug）。
- ⑤：打分 prompt 无参考图比对，纯主观；分数无区分度。

**改进到 V2**：人工角色卡片取代 VLM 身份记忆（`CHARACTER_CARDS`）；风格策略 `style_policy`（character 统一角色画风 + `ANIME_NEGATIVE_PROMPT` 抑制写实/油画/3D）；类别词只注入 human（防拟人）；训练改 TopBiasedRandomCrop（顶部偏置）、rank 32、constant lr、1000 步、质量词注入训练 prompt；新增固定 t 评估 loss；Canny 0.7、CFG 7.0、36 步；删掉"character identity/natural integration"等空词。

### V2 方案（上一版修复，本轮优化起点）

**介绍方案**：卡片 prompt + 混合推理路径（原生 `StableDiffusionXLControlNetImg2ImgPipeline`：img2img 0.72 + canny 0.35，640px）；1000 步重训（顶部偏置裁剪）；固定 t 评估 loss 曲线。

**本次优化前仍存在的问题**：
- ①人物**服装不严格**：卡片身份标签是通用词（white shirt, blue skirt…），生成出"白衬衫+蓝裙"的近似服装而非角色原设（expA_lora_curated / expL_cn035 可见）；
- ②物品配饰**模糊、装饰扭曲**：640 下纹样区域小 + 只有 "surface pattern" 一句描述；
- ③训练仍用"裁方块"方案（仅窗口位置改变），**原图整体信息（全身比例、鞋袜、轮廓）被丢弃**；
- ④评估 loss 曲线有起伏看不清趋势（每次用"当前 batch 图片"评估，不同图难度差 ±0.02）；
- ⑤实验产物散落在 output 根目录，命名与输入不对应。

**改进到 V3（本轮）**：
- ①服装严格化 → 卡片 `identity_tags` 补全角色精确服饰元素（白衬衫高领+金扣、蓝外套+白色分离袖、胸前蓝蝴蝶结、蓝黑束腰+金徽、蓝裙白菱纹、蓝靴金饰、过膝袜蓝结、choker、四叶发饰、腰侧橙红相机、粉白渐变短发、粉紫瞳）。
- ②配饰清晰 → 卡片新增 `object_extra/animal_extra`（精确纹样描述 + 细节词）；实测发现 "smooth ceramic surface / studio lighting" 会诱导"素面白杯"（纹样直接消失，expR2）→ 已删除；实测 768 分辨率会让纹样消失（expR2，构图被重排）→ 物品保持 640 + 修正后描述。
- ③全图信息 → `MixedContentCrop` 混合策略：30% 整图保留（长边 ≤768、面积 ≤640²、8 倍数，不裁剪）+ 50% 顶部偏置（脸/发饰细节）+ 20% 随机窗口；配合 `train.py` 按**每样本实际尺寸**构造 added_cond time_ids（任意长宽比训练）。
- ④曲线可读 → 评估集改为**固定 dataset[0]**（训练开始时缓存一次），消除图片难度抖动；另出"基线 vs 训练后"固定图评估对比图（`output/experiments/eval_compare.png`）。
- ⑤产物归类 → 所有实验图统一收纳 `output/experiments/`（expA~R2b / eval_compare / audit_*，均为本地生成实验，非网络图片）；输入/输出命名对应：`input/human.png ↔ output/result/human_result.png`。

### V3 方案（本轮）

**介绍方案**：V2 全链路 + 上述五项修正；重训 500 步（实测平台期，固定评估集）。

**预期效果**：人物服装贴合角色原设、物品配饰清晰成型、训练利用原图全部信息、曲线可直接读到真实梯度下降、产物整洁可对应。

### v5.1 修正（人物/猫扭曲问题）

**问题**：v5 首版全量复测时人物与猫出现明显扭曲（五官、服饰、姿态），human/human1/human2 尤其严重。

**根因**：v5 的 `resize_fit` 采用"**长边 = 640**"——全身照输出 424×640、宽幅猫 640×352，主体（面孔）只占几十像素，模型被迫在小脸上画五官；同时极端长宽比（0.55 / 1.5+）是 SDXL 分布外输入。旧方窗方案虽然及格，但代价是裁掉头（human1 无头）。

**修复**：`resize_fit` 改为"**短边 = 640、长边 ≤ 960**"（面积 ≤ 640×960 ≈ 0.61MP，与实测可跑的 768² 同级，8GB 安全；仅 >1.5:1 极端图触顶缩整图）。人脸像素量翻倍以上，且比例仍 100% 保留。
