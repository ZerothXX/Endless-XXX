# GitHub 上传整理清单

本清单依据当前源代码的导入关系、动态文件加载路径、网页素材读取及输出目录核查编写。本清单已按训练入口重构更新：移除了旧训练包装和旧 G24 实现，未创建 Git 仓库或提交/上传任何内容，未删除角色数据或权重。

## 输出路径更新（2026-09-11）

标准CLI与网页训练权重为 `output/train_models/`，图片为 `output/result/`，曲线为 `output/curves/`。24GB训练独立输出到 `output/24/` 下的 train_models、curves、logs，不与标准版混放。任务记录和数据副本在 `output/logs/` 子目录，不再创建新的 `web_runs` 或 `training_runs`。下文对这些旧目录的备份建议针对历史文件，不代表当前仍写入这些目录。CLI/网页按 `config.LORA_MODEL_SOURCE`（standard/24）和 `config.LORA_SELECTION_MODE` 共用模型选择规则，默认只读取当前角色 final；旧网页任务清单不再参与角色发现。

## 先分清两个问题

1. **是否属于当前流程依赖**：去掉后训练、推理、网页或现有入口能否继续工作。
2. **是否应该提交 GitHub**：大模型、权重和用户图片可能运行必需，但通常不应放进普通源码提交。

不要为了缩小仓库直接删除本地模型、唯一训练权重或角色原始数据；可以让它们留在电脑上，只不加入版本控制。

### 现有训练权重

`output/train_models/37_final.safetensors` 是当前配置和网页标准角色发现的重要候选，不能为了整理直接删掉。

哈希核查结果：

- `output/train_models/37_best.safetensors` 与同目录 `37_final.safetensors` 的 SHA-256 相同。
- `output/curves/37_best.safetensors` 与同目录 `37_final.safetensors` 的 SHA-256 相同。
- **curves 组与 train_models 组的 SHA-256 不同**，虽然文件大小相同、名字相同，却不是同一份权重。

`curves/` 中两份权重不属于默认加载位置，可单独归档为旧权重，不建议直接丢弃。每组内部如需去重，应先确认自定义配置/旧脚本是否引用对应文件名。此次未删除任何权重。

模型和 LoRA 应单独存储/分发，是否采用大文件存储由维护者决定；不要把大权重直接混进普通源代码历史。

## 四、output 中哪些是可重建缓存，哪些要先备份

| 路径 | 是否默认运行输入 | 整理建议 |
|---|---|---|
| `output/train_models/` | 推理和角色发现会读 | 必须备份所需权重，通常不提交源码仓库 |
| `output/web_runs/` | 历史产物，当前不再自动读取 | 不能整体当日志删；先导出新角色权重和需要的结果 |
| `output/training_runs/`、`output/training_runs_24/` | 新训练产物，默认推理不自动读取 | 含新权重、处理后数据和补出的标签，先备份，不能当临时文件删 |
| `output/experiments/` | 普通入口不自动读取 | 包含隔离训练权重、源代码快照和对照证据，先归档再决定清理 |
| `output/semantic/` | 语义记忆会读取 | 可重建不等于内容完全相同；VLM 重解析可能变化，人工修订/有价值记忆先备份 |
| `output/web_themes/` | 网页会读缓存 | 在模型与原素材齐备时可重建；保留人工审核结果或待对照版本后再清理 |
| `output/result/` | 常规流程主要向此写出 | 历史结果、提示词和 JSON 不是运行必需，建议挑选后归档 |
| `output/logs/` | 常规流程主要写出 | 诊断后可归档，不提交原始路径和私人日志 |
| `output/curves/*.png`、`*.csv` | 不决定推理 | 可选展示/实验依据，需标注对应训练版本 |
| `output/curves/*.safetensors` | 不属于默认加载位置 | 见上文：和当前标准权重不同，归档为旧权重候选 |

`input/web_workspace/` 是当前网页任务输入目录。任务仍在运行、排队，或还要重启旧任务时不要清理；不需要恢复任务后可以归档/清理，通常不提交。

注意网页 `job.json`/`spec.json` 可能记录本机绝对路径。单纯复制 `web_runs/` 到另一台电脑，不保证任务重启或角色注册仍能成功。

## 六、建议的实际整理顺序

1. 先在仓库外备份当前有效模型、所有想保留的 LoRA、源角色图与标签。
2. 按核心代码表确定提交范围，保留两个容易遗漏的依赖：`dataset/data_preprocessing.py` 和 `training_run.py`。
3. 保留 pm/bb 原素材和 README 使用的17张图片；如果没有公开权限，先更换或删去对应引用。
4. 将备份、历史提示词、旧上传与实验资料移至仓库外归档；不要与发布源码混在一起。
5. 为模型、输出、用户输入、缓存、私有数据和工具会话设置忽略规则，但不要整体忽略含有必需源码/素材的 `dataset/`、`f_example/`、`histories/`。
6. 整理后运行 `python -m unittest discover -s tests -v`；再启动 `python web_ui.py`，检查封面、角色列表和缓存主题。
7. 在目标运行环境分别验证一次训练、推理和主题构建；单元测试通过不能替代模型加载与 GPU 端到端测试。
8. 提交前检查待提交文件列表、大文件、绝对路径、私有图片和凭据。发布动作、LICENSE 选择和任何文件删除都由维护者决定。

本次已完成上述训练入口整理，并同步更新 README 和本清单；没有代为编写可能误排除文件的 `.gitignore`，没有批量清理数据或历史目录。后续根据最终公开的数据/功能范围，再定稿忽略规则更安全。
