# 本地角色工作室与自动主题

## 启动

在项目根目录、原有 DL Python 环境运行：

```powershell
python web_ui.py
```

浏览器打开 http://127.0.0.1:7860 。前端直接连接本地模型、文件和 GPU，不需要 Node，也未上传到云端。可用 `python build_theme.py 37` 单独预计算主题。

## 当前实现

- 封面名称为“无尽的xxx”，无 pm；背景有缓慢光带、粒子和连线。遵循系统减少动态效果设置。
- 默认生成页面参考图7：蓝色玻璃云框、左侧结果区、右侧横屏上传区、底部 pm 和 bb。窄屏单独适配；返回后重新进入生成页恢复默认主题。
- 选择已训练角色后应用角色主题。pm 保持原图，bb 仅对彩色配饰区域着色；配饰使用角色参考图抠出的真实素材，不用固定图案替代。
- 多图上传、预览和删除、结果查看、日志/进度、暂停与重新开始、角色训练参数与标签文件入口已接入本地服务。
- GPU 工作通过单一队列、独立子进程串行执行。训练后可勾选构建主题，待训练进程退出后执行，不另训模型。

## 泛化流程，不绑定角色37

`dataset/<角色>/images + captions.txt / 已有角色描述卡 → 前景与配饰识别 → 配色统计 → 主题 JSON → 统一 CSS 变量和配饰布局`

已有透明通道优先使用；可靠白底用边缘连通背景抠图；其他图片使用现有 SAM2，带正负点和框约束，避免仅按掩码分数选中背景。无标签的资料可调用已有 Qwen VL 判断参考图类型，随后卸载，再调用 SAM2。

全身/服装参考的采样权重大于脸部/配饰特写，避免角色训练集头部过采样把整个页面变成肤色、发色。输出保留来源、掩码、原始统计与设计配色，便于核查。

角色权重用于确定角色可用性、对应关系和缓存失效；当前主题构建并不从 LoRA 张量反推配色，也没有声称借助 LoRA 生成了新的界面素材。原有 SDXL 和角色权重用于实际图片转化，现有分割/视觉模型用于主题解析。未增加小模型或辅助训练，因为当前提取流程不需要训练；这不代表所有角色的视觉质量已获验证。

## 文件与安全边界

- 服务与任务：`webapp/server.py`、`webapp/worker.py`。
- 主题构建：`webapp/theme.py`、`webapp/segmentation.py`。
- 页面：`webapp/static/index.html`、`style.css`、`app.js`、`theme.js`、`cover.js`。
- 主题缓存：`output/web_themes`，按参考图/标签/角色权重文件元信息及流程版本生成指纹。
- 网页训练权重与CLI共用 `output/train_models`，图片共用 `output/result`，曲线共用 `output/curves`；任务状态和日志在 `output/logs/web_tasks`，上传输入仍在 `input/web_workspace`。不再创建 web_runs。
- 新角色训练建立新的 dataset 子目录；拒绝覆盖同名已有角色。共享输出目录内的同名权重/结果会覆盖，需提前备份；旧主题输出不迁移。
- 仅监听 loopback；写接口有本地令牌、Host/Origin 检查，限制上传数量/像素量，文件接口不开放任意路径。

## 验证与限制

已实际用角色37完成 SAM2 主题构建、缓存与浏览器切换。发现并修正背景误选、特写主色偏置和 bb 掩码整块着色问题。版本5的37主题主色为 `#8187c6`，点缀为 `#d198ad`：由资料得到，未写死图8的蓝色。桌面1600×900和窄屏进行视觉检查。

单元测试覆盖前景、配色区分、合成另一角色的完整缓存流程、路径与写接口限制、封面名称和素材约束。此次未启动新的完整训练，也未通过网页跑完实际 SDXL 多图任务；这些链路仍需用户训练/推理环境中的端到端验证。

当前视觉是图7/图8构图方向的实现，并非像素级复刻。复杂插画的分割仍可能局部不准，主题标记为需要视觉复核。未自动提取签名，也未生成新的角色配饰变体；只有可识别的真实参考配饰才显示。未验证真实第二角色数据集，合成数据的配色泛化测试不能替代实物验收。

暂停会终止任务进程；重新开始不是断点续训。暂停后的训练重启使用该任务原参数，不应用后来修改的表单值。主题构建失败会报告错误，不用角色37的结果冒充其他角色主题。
